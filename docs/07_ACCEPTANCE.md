# Toymoil 验收原则

## 证据层级

一个功能需要分开描述：

1. Designed：设计已经记录，但没有实现。
2. Authored：场景或资源在编辑器中可见、可检查。
3. Machine checked：静态检查或自动测试通过。
4. Runtime verified：真实 Godot 运行中完成指定行为，没有相关错误。
5. Human accepted：用户实际操作并接受视觉、可读性和手感。

低层级证据不能替代更高层级。截图不能证明完整交互，自动测试不能证明手感，场景树
存在也不能证明运行正确。

## 每阶段最小闭环

- 需求和非目标已经写清楚。
- 编辑器中的正式内容与文档描述一致。
- 相关静态检查和自动测试通过。
- 使用真实运行环境完成一条正常路径和一条失败或重置路径。
- 人工检查画面与操作，不用调试代理替代正常玩家体验。
- 证据、失败和下一步写入开发分支状态文档。

## 视觉验收

- Sprite 不暴露纸片侧面或产生异常透视。
- 玩家、危险、命中和出口的视觉层级明确。
- 地形高度、接触点、阴影、遮挡和弹道一致。
- 武器、手部和特效锚点在方向切换时稳定。
- 彩色灯与后处理不破坏身份色和像素轮廓。

## 真实性规则

没有证据时使用 planned、in progress、unverified 或 blocked。只有实现、验证和状态
记录都完成，才可以写 done；涉及视觉和手感时，必须经过人工接受才算最终完成。
