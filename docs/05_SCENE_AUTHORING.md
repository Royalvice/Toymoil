# Toymoil 场景制作

## Authored 的含义

Authored 内容已经保存进 Godot 场景或资源。打开编辑器时可以直接看到、选择、移动、
检查和修改。它可以由人摆放，也可以由工具生成后保存；关键是它不只存在于运行期间。

## 主场景规则

主场景中的持久可见内容必须所见即所得：

- 房间地面、墙体、主要建筑与持久装饰。
- 正式相机及其构图范围。
- 影响主画面的灯光和环境设置。
- 常驻玩家或用于审查的角色实例。
- 碰撞、导航区域、出生点、门和关键交互标记。

禁止以空节点作为默认主场景，再在 _ready() 中创建整个房间、角色和主要环境视觉。

## 可以运行时生成的内容

- 波次中的敌人实例。
- 弹体、命中特效、短生命周期粒子和 Decal。
- 掉落物与一次性奖励。
- 根据状态临时出现的提示和交互反馈。

每种动态内容必须有独立模板场景或可编辑资源，能够脱离完整游戏单独预览。运行时只
负责选择、配置、播放和回收这些模板，不能把视觉结构藏在脚本常量中。

## 工具生成内容

GridMap、MeshLibrary、导航、碰撞或批量装饰可以由编辑器工具生成，但生成结果必须
保存并重新打开后保持一致。生成脚本不能成为玩家唯一能看见场景的方式。

## 编辑与运行边界

- 编辑器预览证明布局存在，不证明交互正确。
- 运行时验证证明逻辑执行，不证明视觉被接受。
- Reset 可以清理临时对象和状态，但不能依赖重建整个持久世界来恢复基线。
- 调试场景可以简化内容，但不得成为与正式游戏不同的第二套实现。

## 场景审查清单

1. 不运行游戏时能否看见完整持久空间？
2. 相机、灯光、玩家、碰撞和导航能否在场景树中定位？
3. 动态模板能否单独打开并预览？
4. 主要比例和锚点是否来自资源，而不是隐藏脚本常量？
5. 保存、关闭、重新打开后，编辑器画面是否一致？
