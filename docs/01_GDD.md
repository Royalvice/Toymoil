# Toymoil 游戏设计

## 当前游戏假设

Toymoil 以房间或小型区域为主要行动单位。玩家探索空间、遇到事件或敌人、完成
战斗或交互、获得改变后续选择的奖励，然后进入下一个区域。

```text
观察空间 -> 进入遭遇 -> 行动与应对 -> 解决威胁 -> 获得奖励 -> 继续前进
```

这个循环是当前设计起点，不等于已经确定为 Roguelite，也不预设局外成长结构。

## 玩家体验目标

- 走进一个房间时，能迅速理解可通行区域、高差、遮挡、危险和出口。
- 角色动作有明确起止、重量和恢复时间，不像无摩擦地滑动。
- 武器或能力在射程、节奏、空间控制和风险上产生真实差异。
- 敌人通过站位、预警和组合制造选择，而不只是增加生命值。
- 奖励改变接下来的打法，而不是只提升一个不易感知的数字。

## 空间设计

房间可以包含平地、楼梯、坡道、高台、坑洞、门、掩体、机关和可遮挡前景。高度
既用于视觉层次，也应逐步参与移动、命中、视线或区域控制。

地图的 3D 结构与像素细节可以由不同媒介承担：结构负责真实空间，贴图、Decal
和 Sprite 负责图案、磨损、动画装饰与高辨识度信息。

## 角色与内容职责

- 玩家角色：移动、回避、攻击、交互及资源管理的载体。
- 武器与能力：定义节奏、覆盖范围、风险和空间用途。
- 敌人：通过移动、站位、预警和协作提出问题。
- 房间：组合地形、敌人、目标和奖励，形成完整遭遇。
- VFX 与音画反馈：解释状态、危险、命中和结果，不承担游戏规则。

## 尚未决定

以下内容必须通过早期可操作原型比较后决定：

- 移动与瞄准是否独立。
- 鼠标自由瞄准、手柄双摇杆、方向攻击、锁定或辅助瞄准的关系。
- 跳跃、翻滚、冲刺和防御中哪些是基础动作。
- 关卡是连续世界、房间网络还是两者结合。
- 单局、局外成长、角色切换和装备结构。
- 首个正式切片需要多少武器、敌人和房间。

在这些问题锁定前，技术架构不得把某一种控制或循环写死为产品事实。
