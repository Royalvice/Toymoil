# Toymoil 需求

## 已确认需求

### 产品

- Toymoil 是一款游戏，不是面向用户销售的模板库。
- 项目采用 Agent-first 扩展方式，但架构必须服务于实际游戏体验。
- 引擎采用 Godot 4.x，主要游戏代码使用 GDScript；开发开始时再固定具体版本。

### 空间与表现

- 世界使用真实 3D 坐标；X/Z 为地面，Y 为高度，保持 1:1:1 比例。
- 玩家、敌人、武器、弹体和主要 VFX 使用 2D Sprite 表现。
- 正式视角下不得看见 Sprite 的纸片侧面，也不得依赖非均匀世界缩放修正外观。
- 玩家、敌人和弹体能够参与真实高度运动与地形关系。
- 地图允许混合 GridMap、3D Mesh、Decal 和 2D Sprite。
- 3D 灯光与像素角色可以结合，但不能破坏角色轮廓和身份色。

### 场景制作

- 持久世界、相机、灯光和常驻角色在主场景编辑器中必须可见、可选、可调整。
- 运行时可以生成波次敌人、弹体、掉落和短生命周期 VFX。
- 每类动态对象必须拥有可单独打开和预览的模板场景。
- 工具生成的正式内容必须保存为可编辑资源，而不是只在运行期间存在。

### 工程与质量

- 游戏规则、视觉表现和内容数据应保持职责清晰。
- 模块通信优先直接调用、明确引用和局部 Signal；事件平台只在真实需求出现后设计。
- 从最小可操作原型开始，只有重复问题被实际验证后才抽象公共框架。
- 设计结论、编辑器状态、机器检查、运行证据和人工 Play Review 分开记录。
- 任何“完成”或“可玩”声明必须有对应证据。

### 许可

- 项目代码采用 GPL-3.0。
- 美术优先采用 CC0-1.0 或公有领域等最宽松来源。
- 第三方与 AI 生成资产必须具备来源、许可和派生记录。

## 待原型验证

- 相机使用正交还是透视。
- 相机角度、旋转自由度、跟随方式和房间构图。
- 内部画面尺寸、像素密度和输出缩放策略。
- 移动、瞄准、攻击、回避和高度动作的最终输入模型。
- Sprite 使用几方向、哪些动作以及是否需要逐帧法线修正。
- 第一个完整房间的内容规模和目标平台。
- 音频、触感、存档、进度和设置系统的首版范围。

## 当前基线不包含

- 已选定的相机参数或控制方案。
- 已承诺的 Addon 数量、公共 API 或内容注册平台。
- 已实现的角色、武器、敌人、房间、UI 或运行时。
- 可运行 Godot 项目、发布包或性能结论。
